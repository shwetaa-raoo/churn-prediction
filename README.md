# Telecom Customer Churn Prediction System

A machine learning system that predicts customer churn for an Indian telecom setting (prepaid and postpaid), with model comparison, feature importance analysis, and an interactive Streamlit dashboard.

> **Data note:** Airtel, Jio, Vi and BSNL do not publish customer-level data, so this project uses a **synthetic dataset** (10,000 customers, 23 input features) generated by `generate_synthetic_telecom.py` with a fixed seed. Operator names are labels only and have no direct effect on churn. Churn is produced by hand-written rules plus random noise, so the model learns those rules, and the results say nothing about any real operator. The goal is to demonstrate the full ML workflow, not to draw business conclusions.

## Stack
- **Scikit-learn** — Logistic Regression, Random Forest, Gradient Boosting, preprocessing
- **imbalanced-learn (SMOTE)** — optional class-imbalance experiment (off by default, see below)
- **Pandas / NumPy** — data processing and feature engineering
- **Streamlit** — interactive prediction dashboard
- **Matplotlib / Seaborn** — visualizations

## Project structure

## Usage

**Step 1 — (Optional) regenerate the dataset:**
```bash
python generate_synthetic_telecom.py   # then move the CSV into data/
```

**Step 2 — Train the models:**
```bash
python train.py
```

This will:
- Load the dataset and drop the customer ID
- Engineer `recharge_per_gb` and `overdue_days` features
- One-hot encode categoricals and scale numerics (fit on the training split only)
- Train and compare 3 models (Logistic Regression, Random Forest, Gradient Boosting)
- Save the best model, ranked by ROC-AUC
- Generate a feature importance chart

**Step 3 — Launch the dashboard:**
```bash
streamlit run app.py
```

## How it works

1. **Data**: Prepaid/postpaid customers with profile, recharge (₹), plan validity, usage, and network-quality features. About 18% of customers churn.
2. **Feature engineering**: `recharge_per_gb` (₹ paid per GB used) and `overdue_days` (days past plan expiry without recharging).
3. **Class imbalance**: With ~18% churn, always predicting "no churn" scores ~82% accuracy, so accuracy alone is misleading. Models are ranked by **ROC-AUC**, and churn recall is reported alongside. SMOTE is available via `USE_SMOTE = True` in `train.py`; it raised churn recall for Logistic Regression from about 12% to 67% at the 0.5 cut-off but dropped accuracy to about 68% and left ROC-AUC essentially unchanged, so it is off by default.
4. **Risk bands**: Because probabilities rarely exceed 0.5 on imbalanced data, the predictor uses Medium ≥ 0.20 and High ≥ 0.35. On the held-out test set these bands had actual churn rates of roughly 10% (Low), 27% (Medium) and 48% (High).
5. **Prediction**: The dashboard form is generated from the saved input schema, so it always matches the training columns. Encoding and scaling are applied by the saved preprocessor.

## Results (held-out 20% test set, seed 42)

| Model | Accuracy | ROC-AUC | Churn recall @ 0.5 |
|---|---|---|---|
| Logistic Regression (best) | 0.830 | 0.749 | 0.116 |
| Random Forest | 0.823 | 0.724 | 0.033 |
| Gradient Boosting | 0.829 | 0.722 | 0.139 |

Majority-class baseline accuracy: 0.820. Logistic Regression wins on ROC-AUC, consistent with churn being generated by roughly additive rules.
